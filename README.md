# shack-mini

ダンジョンSLG 企画案1「どちらかが辿り着けばいい」の試作（MVP）です。

バラバラに落とされた2人（A・B）を操作し、階段を目指すターン制ダンジョンSLGです。
どちらか1人が階段に着けば、2人そろって次の階層へ進めます。2人とも倒れたらゲームオーバー。到達階層がスコアです。

素のHTML／CSS／JavaScript（ESモジュール）だけで動きます。ビルドや依存パッケージはありません。

## 遊び方

- **目的**：A・Bのどちらかを階段（黄色いマスの ▼）に乗せ、「降りる」を選ぶ
- **ターン**：味方を好きな順に1体ずつ動かす。全員が行動すると自動で敵のターンになる（設定で手動にもできる）
- **次に何をするか**はマップ上端の案内帯に出る（例「A 青で移動／赤い敵で攻撃」）
- **操作**（タップ／クリックのみ）
  - 味方をタップ、または下のA・Bのチップをタップ → 選択。青いマスで移動、自分のマスで移動せずに行動へ
  - 攻撃できる敵は最初から赤く表示され、**タップするだけで攻撃**できる（予測ダメージ付き、倒せるときは ✕）。回復できる味方（水色）も同じ
  - 行動ボタン：攻撃／召喚／回復／降りる／待機／戻す（移動の取り消し）。召喚はボタン → 種類 → 緑のマス
  - 1体が行動し終えると、まだ行動していない味方が自動で選ばれる（A → B → 召喚）
  - 敵をタップすると、その敵の情報と、次の敵ターンで届く範囲（赤）を表示
  - マップはドラッグで動かせる。「全体マップ」で全体表示、タップした地点へカメラを移動
- **画面の見方**
  - 未行動の味方は白いリング、行動済みは灰色で「済」、選択中は黄色いマスと頭上の ▼
  - HPバーは残りの割合で緑 → 黄 → 赤
  - 上部バーに「味方の番／敵の番」
  - 敵のターンは短い演出で再生される（攻撃した敵からの矢印、ダメージ表示、画面中央の帯）。タップで早送り
  - ログは敵の行動が赤（「敵」タグ）、味方の行動が青（「味方」タグ）。ログ欄をタップすると直近20件まで広がる
- **設定（右上の ⚙）**：「遊び方（簡易マニュアル）」で遊び方・色の見方・召喚の一覧を読める。次の3つも切り替えられる（すべて既定でON。ブラウザに保存）
  - 自動でターン終了
  - 敵を直接タップで攻撃（回復も同様）
  - 石像は自動で行動済み（動けない石像を毎ターン選ばない）
- **ルールの要点**
  - A：近接で頑丈。B：射程2〜3で召喚向き
  - ダメージは `攻撃 − 防御`（最低1）。必中・反撃なし
  - 敵を倒したユニットだけがEXPを得る（召喚ユニットが倒したら召喚者へ）
  - 倒れた方は次の階層でHP1で復活。2人とも倒れたら1階からやり直し
  - 召喚（MP消費）：石像（壁役）／猟犬（偵察）／戦士（火力）／癒し手（回復）。1人2体まで、階段を降りると消える
  - 長居すると8ターンごとに増援、40ターン目に強敵「徘徊者」が現れる
- ベスト到達階層はブラウザの localStorage（キー `shack-mini.best`）に保存します。ゲーム名変更前のキー（`dungeon-slg-1.best`）の記録は引き継ぎません
- URLに `?seed=12345` を付けるとシード固定で開始できます（現在のシードは設定画面に表示）
- `?debug` を付けると、ブラウザのコンソールから `dslg.state` でゲーム状態を見られます（開発用）

## ローカルで動かす

ESモジュールを使うため、`index.html` を直接（`file://` で）開くと動きません。簡易サーバーを立ててください。

```sh
python3 -m http.server 8000
# → http://localhost:8000/ を開く
```

テスト（Node 20以上。追加インストール不要）：

```sh
npm test
```

## GitHub Pagesで公開する

1. GitHubにリポジトリを作り、main ブランチのルートに `index.html` を置く（このリポジトリの構成のままpushする）
2. Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `(root)` にする
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける

パスはすべて相対パスで書いているので、サブディレクトリ配信でもそのまま動きます。

## 構成

```
index.html / style.css
src/main.js          起動、シード決定、各モジュールの接続
src/config.js        数値設定（バランス調整はここだけ）
src/logic/           ゲームロジック（DOM・Canvasに触れない。node --test でテスト）
src/view/            描画・入力・HUD
tests/               ロジックのテスト
```
